## What's new in alpha.7

**No genesis reset.** Genesis and chain-id are unchanged from alpha.6 — existing chain
state carries over and balances are preserved. This is the first alpha that upgrades in
place. Upgrade every node together anyway: consensus behaviour changed (see *Upgrade
notes*), and this remains a coordinated-upgrade network.

### Fixed — these affected anyone running alpha.6

- **Transactions were silently lost at the RPC boundary.** `POST /tx` answered
  `accepted: true` the moment the transaction was queued on a channel, *before* the
  mempool gate ran. The real verdict happened later and every rejection was dropped to a
  log line the submitter never saw — so a transaction could be reported accepted,
  gossiped, packed into a block, and then discarded, with the sender told it succeeded.
  `/tx` now waits for the actual admission verdict and returns it: `200` when genuinely
  admitted, `400` with the real reason when rejected, `202` only if the node is too busy
  to answer in time. This was the structural root of the bugs below.

- **The mempool accepted transactions consensus would refuse to apply.** The ingress gate
  checked only `fee >= MINIMUM_FEE`, while apply additionally rejects a transfer to a
  not-yet-existing account below `ACCOUNT_CREATION_FEE`, and any transfer below the dust
  limit. Transactions satisfying the gate but not apply were accepted by every node,
  gossiped, packed, then dropped during block production. This is the shape that had been
  silently killing every faucet dispense and every `commputer send` to a new address. The
  gate now enforces exactly what apply enforces.

- **`commputer bond` reported success for bonds the sender could not afford.** Apply
  deducts the fee *first* and then requires the remaining balance to cover the bond, so
  "bond everything I have" — the natural move for a new user who just claimed from the
  faucet — was always rejected at apply and silently discarded, while the CLI printed
  success. `bond` now checks the balance before signing and explains the fee-first
  deduction. Bonding is the only documented route to becoming a PoUW committee candidate,
  so this was a new operator's first broken step.

### Security

- **Closed a block-grinding attack that was live on the network.** To tolerate clock skew,
  leader validation accepts three views at once, so up to three addresses can be legal
  leaders at the same height. Candidates were then arbitrated by *lowest block hash* — a
  value a producer can re-roll for free by nudging the timestamp or reordering
  transactions. Any node legal in an adjacent view could grind until its hash sorted
  lowest and steal the round from the primary leader. This required no open validator set;
  it worked inside the pinned founder trio. Candidates now rank by the producer's **view
  offset** (a pure function of height and validator set, so it cannot be ground) and only
  then by hash, so the primary leader always outranks a fallback.

- **Closed the same hole in a node's own ballot.** The first fix covered the vote sent to
  peers but not the node's own self-vote, which still used lowest-hash. With a
  three-node quorum of two, that single ballot was enough to carry a ground block — the
  attack was still open through the vote we cast ourselves. Both ballots now use the same
  rank.

- **Fixed a quorum that was exactly half at six validators.** The threshold curve returned
  3-of-6, which permits two disjoint quorums and therefore two conflicting finalized
  blocks at the same height. Unreachable with today's three validators; reachable the
  moment a fourth and fifth join. Six validators now require four.

- **Validator-set derivation is now single-sourced and stake-aware.** Validation and
  production previously derived the set through duplicated logic that the code's own
  comments warned had to stay in agreement. There is now one derivation with a
  deterministic order (nodes that disagree on ordering would disagree on the schedule).
  Live behaviour is unchanged.

### Groundwork — present but inactive

Most of this release's diff builds the stake-weighted proposer schedule that will replace
plain round-robin when the validator set opens beyond the founder nodes. **None of it
decides anything yet.** It runs in shadow mode: each node computes the schedule it *would*
use, commits it to a digest, and logs the result for cross-node comparison, while the live
round-robin continues to choose proposers. You may see new `shadow schedule` log lines;
they are informational. An overnight soak across 22 samples and 22 consecutive epochs
showed all three nodes deriving byte-identical schedules with zero disagreements.

### Upgrade notes

- **Upgrade all nodes together.** Consensus tie-breaking and view-change target selection
  changed. A mixed alpha.6/alpha.7 network can disagree about which block wins a contested
  height or which validator takes over after a view change.
- **The upgrade is one-way for the data directory.** alpha.7 adds a column family to the
  node database. It is created automatically when alpha.7 opens an alpha.6 database, but
  older releases do not know about it and will not open a database that has it. To roll
  back to alpha.6, wipe the data directory and re-sync.
